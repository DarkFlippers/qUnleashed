## Main changes
- Version: 0.16.0
- Diagnostics: **The app reports its own failures now** - Settings -> Diagnostics, renamed from Log, carries two switches - **Share logs with developers**, on by default, and under it on Android and iOS **Include a replay of the screen**, which records while the app is open and sends the recording only when something fails. A crash or a caught failure goes out with the app version and the build it came from; card data, keys, captures and coordinates do not, and the hex table, the signal plots, the Flipper's screen, the map and the Pixel Draw canvas are hidden from the replay as it is recorded rather than afterwards. A one-time notice says what is sent before anything is, and **Turn it off** opts out in one tap. The in-app log list, its Copy and Clear buttons and the 500-entry buffer behind them are gone - a shipped build with reporting off records a failure nowhere, which is the price and is stated rather than hidden (by @mishamyte | PR #292, #295, #306)
- Archive: **Drag and drop in the file manager** - files and folders dropped from another app upload into the folder on screen, and files drag out of the Flipper into another app or onto the desktop. Keys drag out of the archive categories and favourites the same way, and a selection drags out whole (by @apfxtech)
- Archive: **Replace, Skip or Rename when a file is already there** - asked once, before anything is written, instead of overwriting without a word. One answer can cover every conflict, and files whose checksum matches can be left alone (by @apfxtech)
- Archive: **Transfers can be cancelled** - downloads, uploads and copies each get a Stop on their row or on the progress bar. On firmware that reads files in parts the read stops at the next part, and the bar keeps moving until the last one has arrived rather than freezing. Firmware that sends the whole file regardless is given eight seconds, after which the row clears without claiming the transfer was cancelled (by @apfxtech)
- Archive: **Upload a whole folder** from the + menu, subfolders included (by @apfxtech)
- Archive: **One large download at a time** - a file bigger than one firmware packet (512 bytes) is refused while another is in progress rather than piling a second one onto the link. There is no queue, so it has to be asked for again; small files still open straight away. Opening and sharing the same file at once downloads it once. A file bigger than 512 bytes drags out of the file manager again - the drag started that file's own download, which then counted as the other one and cancelled the drag; a drag refused while another download runs now says so (by @apfxtech)
- Archive: **A hex mode in the editor**, so a binary file opens in it instead of refusing to open at all (by @apfxtech)
- Archive: **Group a category by its folders, and keep the order you picked** - a category listed its files by name and nothing else, which scatters a collection the size of Flipper-IRDB: the folders are the only categories such a collection has, and by name `LED_Lighting/10-key_Candle`, `Miscellaneous/1533` and `Car_Multimedia/2005_Volvo_XC-90` land next to each other. A sort button in the toolbar now offers **Folder, then name**, which keeps each folder together and orders its files inside it; turning it around reverses the folders and leaves each one's names A-Z. The choice is remembered across launches and shared by every archive table, and a table with no column for the sort you picked falls back to name and gives it back when you return to one that has it. The sheet carries every sort the table offers, so the ones whose columns a narrow window hides are reachable again (by @mishamyte | PR #312 | Closes #122)
- Tools: **Sub-GHz seed recovery for FAAC SLH, Genius, BFT and Erreka remotes** - reads a capture from the Flipper's `seed_capturer` app, recovers the seed in the app with no server, and saves a transmittable `.sub` under Sub-GHz -> Saved. A capture that missed a few presses still solves, so the whole burst does not have to be caught. A capture can be deleted from its own row, including ones taken before this shipped. A recovery that cannot be saved names what is missing, instead of putting "Seed recovered" over a card with no figures, no button and no sentence anywhere (by @mishamyte | PR #264, #273, #286, #308 | Closes #142, #269, #294)
- Tools: **Hardnested MIFARE recovery actually runs** - it failed on every attempt with an engine error before doing any work. It now has a Stop, refuses to start without the memory it needs, and its brute force uses the vector instructions the CPU has instead of the slowest variant (by @mishamyte | PR #236, #242, #259, #287)
- Tools: **MIFARE recovery says what it is doing and keeps what it found** - keys already known are skipped, a failed save retries the write rather than the whole run, the user dictionary is backed up before it is overwritten, and Stop also works while the logs download (by @mishamyte | PR #235 | Closes #234)
- Tools: **MIFARE key recovery works on iOS and macOS** - it never had. Reading a `.nested.log` ended with "Candidate generation is unavailable on this build" for static-encrypted cards, and mfkey32 and weak-nested recovery were just as dead, failing with a generic error instead of that one. The attack code was compiled into the app and then discarded at link time, because nothing outside Dart names those entry points in a way the linker can see (by @mishamyte | PR #231 | Closes #229)
- Tools: **Recovering MIFARE keys no longer looks frozen while it saves them** - a static-encrypted card produces tens of thousands of candidate keys, and writing that dictionary to the Flipper was a single step with nothing on screen moving for the whole of it. Over Bluetooth that is minutes. It now reports how far along it is, across every card in the run, and **Stop really stops it** instead of carrying on against a device you have walked away from (by @mishamyte | PR #233)
- Tools: **Wrist Remote** - the Flipper can be driven from Android media controls, including a wrist device (by @MrSoichi | PR #82)
- Tools: **An in-app log screen**, and a route for errors nothing else catches - what a shipped build could be asked for after something went wrong. Superseded by Diagnostics above, and listed because it is what shipped in between (by @mishamyte | PR #90, #93 | Closes #89)
- Pixel Draw: **A canvas-first editor, and one adaptive gallery** - the library and manifest screens are merged into a single screen that fits the window it is in, and the editor is built around the canvas rather than around its toolbars (by @apfxtech)
- Map: **Rebuilt on mobile and desktop** - a draggable pin sheet on phones, a new screen on desktop, and tile loading that works. Location permission is asked for before the service is probed rather than after, the tile attribution stays put, and the sheet toggles from anywhere on its header (by @apfxtech)
- Browser: **The file list is a sortable column table**, with row actions that can be hit and category rows that match their headers (by @apfxtech)
- Connection: **Bluetooth links negotiate their full packet size** - the size was read a moment too early on iOS and macOS, before the system had settled it, and a link that lost that race spent the rest of its life sending packets a twentieth of the size it could carry. Everything over Bluetooth was slower for it, not only key recovery (by @mishamyte)
- Connection: **The picker says which link to let go of** - the app holds at most two links at once, and asking for a third used to fail with a generic "Connection failed". It now says so and tells you to disconnect one (by @mishamyte | PR #212)
- Connection: **Auto-connect failures are visible** - a cable that does nothing, forever, used to be a log line nobody reads. The device page now carries a dismissible card naming the cause, since a timer-driven attempt has no gesture to hang a dialog on and a toast would fade while the condition did not (by @mishamyte | PR #213)
- Connection: **Remote Control follows the Flipper you are linked to**, and the CLI stays on its Flipper across reconnects (by @apfxtech | PR #260, #261)
- Connection: **Device work is bound to the Flipper it started on**, so a swap mid-operation cannot land it on the other one (by @apfxtech | PR #127)
- Device: **A refused reboot is no longer silent** - firmware that declines to reboot (an app is running, or it is busy) used to look exactly like a reboot that happened: the page went to disconnected while the Flipper sat there unchanged (by @mishamyte)
- Device: **A settings page for auto-connect and clock sync**, and a setting for whether the map reads nested archive folders (by @apfxtech)
- Recovery: **DFU works from an Android host** - with a source-built libusb, and errors that name the driver rather than the symptom (by @apfxtech)
- Widgets: **Send an archive key to the Flipper from the Android home screen**, with a key the widget can be pointed at (by @apfxtech)
- Everywhere: **A failure now says why** - roughly thirty surfaces that used to show "nothing to show", a spinner that never ended, or a bare "it did not work" now carry the reason the Flipper or the phone gave. Deleting a key while an app is running says `ERROR_APP_SYSTEM_LOCKED` instead of reappearing seconds later in silence; a restore onto a full card says so; a key that will not open, a send that did not go, a setting that did not stick and an emulation that never started all name their cause (by @mishamyte | PR #134, #180, #181, #183, #184, #185, #186, #188, #189, #190, #191, #192, #193, #197, #200, #201, #202, #214 | Closes #114, #118, #119)
- Names: **One rule for what a file name may not contain**, used by every name prompt, and a name the Flipper's own RPC layer would refuse is refused up front with the rule that refused it. Four prompts that write a typed name to the device validated nothing at all and a fifth refused only a handful, so `gate/one`, a pasted tab or a 300-byte name reached the firmware and came back as "Create folder failed" with no cause named. Sub-GHz names are measured in bytes, so a long Cyrillic name is no longer cut in half on the Flipper (by @mishamyte | PR #275, #285, #303 | Closes #266, #277, #278, #282)
- Apps: **An install says which way it went** - over the link, or by DFU (by @mishamyte | PR #207 | Closes #132)
- Firmware: **One bad field no longer costs the whole directory** - every version of every channel went away at once when a single field upstream changed type. Each entry is read on its own now, one that cannot be identified is skipped and named with its path, and a feed that produced nothing usable says so instead of arriving at the card as an empty directory offering to install a file you pick yourself (by @mishamyte | PR #140 | Closes #133)
- Apps: **One bad entry no longer costs the page** - a malformed catalogue entry, cached app list row or ATP pack member is skipped and named instead of emptying the screen (by @mishamyte | PR #76, #178, #179 | Closes #63)
- Firmware: **An offline launch still shows the directory** it last fetched, instead of nothing (by @mishamyte | PR #209 | Closes #131)
- Archive: **A pull to refresh waits for the refresh** - four tables ended their spinner in the same frame they started it, while the download or the device scan had not begun (by @mishamyte | PR #219, #222)
- Settings: **The update channel and build variant are remembered**; Storage no longer reports a size or a clear it did not manage (by @mishamyte | PR #70, #182 | Closes #64)
- Language: **Ukrainian buttons are set in one typeface again** - the pixel face the big buttons use has no Є, І, Ї or Ґ, and a missing letter is not an error in Flutter: it quietly borrows the system face for that one character. So the firmware button read НЕМА З'ЄДНАННЯ with a serif Є in the middle of it, across fourteen labels. The letters are drawn now, along with Belarusian, Macedonian and Romanian ones and the dashes, ellipsis and arrow the app already used; the slash and И are redrawn; and the face ships once rather than twice under two names (by @mishamyte | PR #299 | Closes #298)
- Language: **Ukrainian** - the picker names every language in that language, and a language nobody has translated yet is no longer offered as English under another name (by @mishamyte | PR #241, #249, #258)
- Language: **Russian says which way the bytes moved** - one word carried download, upload and load at once, so two File Manager failures read identically, one for files coming off the Flipper and one for files going onto it. All 51 messages that had it are split three ways, eight strings that had never been translated are, and all fifteen plurals carry the `many` branch Russian wants for 5 to 20 rather than falling through to `other`. The English source the translator had been quietly correcting is corrected too, including a hint naming a button that does not exist and a message describing the wrong direction (by @mishamyte | PR #71)
- Android: GIF exports are compressed rather than expanded, and the GNSS fix is requested at startup (by @mishamyte | PR #68 | Closes #60, #69)
## Other changes
- Versioning: the version in `pubspec.yaml` is the one being built *toward*, and CI refuses a build whose version has already been released or whose tag disagrees with it. The build number is derived - `100000 + commits on main x 10 + slot` - so every dev build in a cycle shares one name and is still ordered. `docs/releasing.md` is the runbook (by @mishamyte | PR #237, #292)
- Desktop: closing the window disconnects every link first, so the USB serial port is released instead of staying held by a process that would not exit, and the reports buffered on the way out are flushed before the process goes (by @mishamyte | PR #246 | Closes #245)
- Tools: the recovery page's buttons are styled like the rest of the app, and Stop works during the log download (by @mishamyte | PR #243, #239)
- Tools: a build missing its recovery engine says so on every screen, instead of reporting it as a failure that could equally have been a full card or a key the tag refused (by @mishamyte | PR #231 | Closes #229)
- Connection: a link that ends up slow says so in the log, which is the one place a finished transfer can explain why it took as long as it did, and flipperlib's warnings are kept for a bug report instead of being dropped before anything records them (by @mishamyte | PR #232)
- Archive: file colours in the file manager match their archive categories (by @apfxtech)
- Map: the tile notices close after three seconds, the tile preview border draws over the tile, CARTO is marked as needing a key, and the archive map picks up where it left off after a reinstall (by @apfxtech)
- CLI: the session opens without starting RPC (by @apfxtech)
- Notifications: the map notice style is used everywhere, and the custom app bar tooltip is gone (by @apfxtech)
- Security: an archive entry can no longer write outside the folder it unpacks into - the IRDB unpacker had no containment check at all, all-the-plugins left `..` intact so an entry named `../../../evil.fap` wrote outside the pack, and the firmware installer joined the archive root onto `/ext/update` so a relative segment walked out of it on the SD card (by @mishamyte | PR #17)
- Linux: the build is pinned to the oldest system it claims to support. `ubuntu-latest` is not a floor - it is whatever GitHub last pointed the label at, it moved to 24.04 and took a published asset with it, and 0.11.2 unpacked and then would not start on Ubuntu 22.04, Mint 21.x, Debian 12 or Ubuntu 23.10. A check holds the floor now, rather than the pin being trusted on its own (by @mishamyte | PR #301 | Closes #280)
- Diagnostics: one archive loop was 94% of everything the project reported - 2267 entries in four hours from a single session, which overflowed the buffer on the way out and cost two of the three crash reports captured that day. The per-file line is gone, a directory the firmware says is not there is an empty listing rather than a warning, and the scrubber no longer reads a six-decimal duration as a coordinate and redacts it (by @mishamyte | PR #305)
- Infrared: one entry the filesystem refused no longer fails the whole library import, and the unpack is about seven times faster (by @mishamyte | PR #61 | Closes #22, #24)
- Remote Control: the lock state is read out of the status the firmware actually sends, so the page learns whether the Flipper is locked at all - the answer arrives in an empty frame, and on an unlocked device the attempt to read it was rejected into the disconnected path (by @mishamyte | PR #95 | Closes #79, #94)
- Firmware: the firmware carousel syncs when the firmware changes, not twelve times a minute - it synced from `didUpdateWidget` under a five-second battery poll, and each run was a directory call and a fetch (by @mishamyte | PR #136 | Closes #135)
- Pixel Draw: a manifest paragraph with no `Name:` of its own is dropped and counted instead of changing the animation above it, and the manager says a block was skipped rather than reporting a clean read over a file that did something else (by @mishamyte | PR #173 | Closes #171)
- CLI: the terminal says when a keystroke did not arrive, when the link dropped and when the session could not start, instead of looking like a hung Flipper, and the Ctrl-C the page sends on the way out goes through a handler that can actually fire - `dispose` is not async, so the `catch` around it only ever covered the synchronous prologue (by @mishamyte | PR #81, #88 | Closes #21, #80)
- Quality: four ratchet tests hold lines that used to drift - failures reported only at a level release builds drop, catches that record nothing, classes that reach for the device instead of being handed it, and futures nobody awaits or handles. The last went from 119 sites to 21, each remaining one named with its reason (by @mishamyte | PR #101, #102, #105, #107, #108, #111, #113, #115, #121, #149, #177, #216, #217, #218, #221, #223 | Closes #117)
- Quality: 1680 test cases, up from 26 files at 0.12.1, and CI runs them in a random order so none of them depends on being first. `flipperlib` has its own suite, including the RPC queue and the connection-error classifier (by @mishamyte | PR #205, #150)
- Architecture: fifteen decision records under `docs/adr/`, with the ones that carried migration work closed by evidence rather than opinion - `ChangeNotifier` stays, dependencies are passed in, absence is `null`, feed decoding is tolerant. ADR 0013 adds a third log level for failures nothing records, and ADR 0014 settles versioning on SemVer and the build number it forces (by @mishamyte | PR #145, #228, #237)
- Localization: English is the only translation source anyone can edit, enforced in CI, so a Crowdin sync can no longer overwrite a language. Obsolete strings leave Crowdin, plurals no longer trip its checks, and `docs/translating.md` says what a translator needs to know (by @mishamyte | PR #72, #262, #252, #256 | Closes #41)
- Release: every release publishes `SHA256SUMS`, the Android APKs are verified to contain an app before publishing, the macOS and iOS builds refuse to package an app whose recovery entry points did not survive linking, the workflows are linted, Dart formatting is enforced, and the build path can be exercised without cutting a release (by @mishamyte | PR #44, #53, #54, #55, #57, #231 | Closes #32, #51, #50, #30)
- Dependencies: drag and drop uses DarkFlippers forks of super_native_extensions and irondash, built for Android's 16 KB pages; macOS builds target 12.0; flipperlib reads files in parts (protocol 0.30) (by @apfxtech)
- Dependencies: dartufbt reads `application.fam` as the Python it is - 696 of 696 manifests on hand, against 693 (by @mishamyte | PR #247)
- Tools: Wrist Remote names each half of a failure rather than guessing it from the type (by @mishamyte | PR #92 | Closes #91)
- Fixed: a double click is one gesture - opening a file and starting a firmware install were two of the fourteen places it ran the action twice, and the other twelve are guarded now, four of them never audited (by @mishamyte | PR #250, #302 | Closes #244)
- Fixed: Flibler stays in the Tools menu when a build server is set or an earlier catalog build failed, since it can still build (by @mishamyte | PR #251 | Closes #248)
- Fixed: a candidate dictionary that failed to save no longer leaves the progress bar short for the rest of the run (by @mishamyte | PR #233)
- Fixed: the app no longer asks the firmware for a window it will refuse, and no longer sends the same hop twice (by @mishamyte | PR #290 | Closes #288, #289)
- Fixed: a reconnect that raced the initial open was dropped; an interrupted IR library refresh cost the user their library; apps removed from the device still showed as installed; a cached response body was decoded on the calling isolate; the apps table header overflowed its row at every window width (by @mishamyte | PR #78, #84, #87, #67, #65, #220 | Closes #20, #62, #85, #3, #25)
- Fixed: a bad preference no longer kills the app before it starts, a value an older build stored under another type reads as absent rather than being cast, and three settings stores share one load between them (by @mishamyte | PR #125, #128, #204 | Closes #123, #124, #126)
- Fixed: one failed listing no longer deletes a whole category, a Flipper with no apps is told apart from one nobody could read, and the home widget no longer says "sent" for a send that never went (by @mishamyte | PR #194, #195, #196 | Closes #109, #112, #104)
- Fixed: a silent server no longer holds a request open for ever, and every log line no longer pays for a timezone lookup (by @mishamyte | PR #199, #187 | Closes #130, #116)
- Fixed: a cancelled Bluetooth write no longer kills the app on Windows - a write that lost its link was cancelled rather than failed, and the native callback read its result anyway and threw on a thread with no Dart frame on it, so every `try` in the app and in `flipperlib` was downstream of a process that was already gone (by @mishamyte | PR #309 | Fixes #307)
- Fixed: the sheets compare snap sizes exactly so they cannot drift below the minimum, and the Pixel Draw gallery and Map sheets sit above the bottom safe area (by @apfxtech)
